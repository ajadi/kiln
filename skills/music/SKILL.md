# Adaptive game music

The deliverable is a reproducible cue: spec → MIDI → rendered stems → engine resources, every
step a script with fixed seeds, every gate a number. Reference tracks are for analysis only:
never sampled, never used to condition an AI model.

Environment: user-level venv `<venvs>/music` (machine.json `tools_root`/venvs, else
`~/.local/share/kiln/venvs`; Python 3.12+): dawdreamer,
pretty_midi, mido, music21, pedalboard, pyloudnorm, librosa, soundfile (`${extensionPath}${/}skills${/}music/requirements.txt`);
ffmpeg or oggenc on PATH.
Gates: `${extensionPath}${/}skills${/}music/../procedural-audio/scripts/audio_check.py` (`loop`, `stems`, `asset`).

## 1. Adaptive design

- **Vertical layering:** stems play in sync; intensity sets which are audible. **Horizontal
  re-sequencing:** segments switch on beat, bar or end boundaries, through transition or filler
  segments. **Stingers:** short one-shots on the beat grid (arena cleared, boss reveal, death).
  Combine all three.
- States for an action game: Explore 0 → Alert 1 → Combat 2 → Heavy/Boss 3, plus victory and fail
  stingers and a menu theme. Inputs: engaged enemies, player health, boss phase. **Hysteresis:**
  go up at the next bar, come down only after 8–12 s without combat. A MusicDirector (gameplay
  developer) owns the state machine; music assets own no logic.
- Fatigue: loops of 8, 16 or 32 bars; explore cues 2–4 min, combat 60–120 s per level with 2–3
  variants (shuffle); fall back to ambience or silence after N minutes in one state; keep the main
  melody in a rare layer.
- Leitmotifs: 3–5-note motifs for the hero, the enemy, each faction; vary by reharmonisation,
  mode, tempo, orchestration; the boss stinger states the enemy motif.
- Frequency budget: weapons and explosions own the sub transients and the 1–5 kHz bite; dialogue
  lives at 1–4 kHz. Music keeps sub hits short, avoids dense 1–4 kHz parts under dialogue, and is
  sidechain-ducked 3–6 dB by SFX/dialogue buses.

| State | Tempo | Harmony and feel |
|---|---|---|
| Explore | 70–95 BPM | Dorian/Aeolian pads, sparse percussion |
| Tension | 90–110 BPM | ostinato, tritone and chromatic neighbours, pedal points |
| Combat | 130–170 BPM or half-time | Phrygian / Phrygian-dominant, low riffs, 7/8 inserts |
| Victory | — | major/Lydian lift |

One BPM family and key family per suite so segments can be swapped. **Choose BPMs whose beat is a
whole number of samples at 48 kHz** (60·48000/BPM integer): 90, 96, 100, 120, 125, 128, 144, 150,
160, 180 — engines truncate fractional loop points.

## 2. Composing without hearing

1. Cue spec JSON from the bible: tempo, key, metre, bars, section list, stems and their roles,
   motif placement, seed.
2. `tools/music/compose.py` turns the spec into one MIDI file per stem (pretty_midi or mido;
   music21 for analysis). Building blocks: harmony templates (i–bVI–bVII–i, i–bII, pedal point
   under a chromatic ostinato), motif operations (transpose, invert, retrograde,
   augment/diminish, fragment, sequence), rhythm templates (industrial four-on-the-floor with 16th
   hats and metallic percussion; metal 140–180 BPM double-kick 16ths with palm-muted chugs and
   syncopated accents; darksynth 100–120 BPM; drum & bass 170–175 BPM).
3. Theory gates on the MIDI: `music21.voiceLeading.VoiceLeadingQuartet` (parallel/hidden fifths
   and octaves, voice crossing) where voices are meant to be independent; Krumhansl key estimate
   matches the spec (relative major/minor counts as a match); every note inside its instrument's
   range; note density per bar within the section's target; every pitch in key or on the allowed
   chromatic list; no note held across the loop boundary unless the render wraps it (§3).

## 3. Rendering

| Route | When | Tools and licences |
|---|---|---|
| **Synthesis (default)** | always available; deterministic; suits industrial/electronic/hybrid scores | DawDreamer 0.9 (GPL-3; Faust instruments, MIDI render, automation) + pedalboard (GPL-3; EQ, compressor, limiter, reverb). The GPL covers the tools, not the audio they render |
| Soundfonts (opt-in per project) | piano, strings, orchestral pads | FluidSynth (LGPL) `fluidsynth -ni -F out.wav -r 48000 bank.sf2 cue.mid`; FluidR3_GM (MIT) or GeneralUser GS (free for commercial use; author cannot vouch for every sample); credit the bank. Weak for metal guitars |
| AI models (policy `audio_generators`, default off) | ideation only, never final stems unless the user decides | ACE-Step 1.5 (MIT code and weights; BPM/key/metre control) or Stable Audio Open (Stability Community licence: free under $1M revenue, attribution). **Not**: MusicGen (weights CC BY-NC), Udio (no downloads), YuE2 (company licence), Suno free tier (non-commercial). AI output is not copyrightable in the US; tell the user |

- **Seamless loops: render two cycles and keep the second** — it already contains the release
  tails and reverb wrapped from the end into the start. A single-cycle render clicks at the seam.
- Mix and master per cue with pedalboard; normalise all stems of a cue **as a group** (never each
  stem alone); cue target −18…−20 LUFS-I, true peak ≤ −1 dBTP; the title-wide mix target is
  qa-audio's (−24 ±2 LUFS on home platforms over ≥ 30 min).
- Encode Ogg Vorbis q6–q8. Godot needs Ogg or MP3 for beat-synced transitions — WAV has no
  `bpm`/`beat_count`/`bar_beats`. Godot: set them (and `loop`) with the engine-godot skill's
  `scripts/import_edit.py set <cue>.ogg.import --param loop=true --param bpm=96 ...`, then
  `filesystem_manage reimport` (engine-godot `references/import-settings.md`).

## 4. Gates (record in `tools/music/reports/<cue>.json`)

| Check | Method | Gate |
|---|---|---|
| loop length | `audio_check.py loop --bpm --bars --beats-per-bar` | exact sample count |
| seam | same | jump ≤ 99th-percentile step |
| loudness, true peak | `audio_check.py asset --target-lufs -19 --tol 1` on the cue mix | in target; ≤ −1 dBTP |
| stems | `audio_check.py stems <stems> --mix <mix>` | equal length/rate; residual < −60 dBFS |
| tempo | `librosa.beat.beat_track` + onset-to-grid offset | ±1 BPM; ≤ 10 ms |
| key | `chroma_cqt` + Krumhansl vs the spec | match (relative keys count) |
| dynamics | LRA from `audio_check.py asset` | ambient 4–10 LU, combat 3–6 LU (heuristic) |
| repetition | recurrence matrix, unique-bar ratio | combat ≥ 60 s before an exact repeat (heuristic) |
| spectral room | band energies < 60 / 60–250 / 250–1k / 1–4k / 4–12k Hz vs the brief's reference profile | combat 1–4 kHz ≤ reference − 2 dB (heuristic) |

## 5. Engine implementation

**Godot 4.3+** (resources created through the Godot AI MCP):
- Ogg import: `bpm`, `beat_count` (loop end), `bar_beats`, `loop`, `loop_offset`.
- `AudioStreamInteractive`: clips + `add_transition(from, to, from_time NEXT_BEAT/NEXT_BAR/END,
  to_time START/SAME_POSITION, fade_mode, fade_beats, use_filler_clip, filler_clip, hold_previous)`;
  switch with `get_stream_playback().switch_to_clip_by_name(&"combat_hi")`.
- `AudioStreamSynchronized`: up to 32 stems; tween stem volumes (set every mix block → zipper
  noise if stepped). `AudioStreamPlaylist`: up to 64 streams, shuffle, `fade_time`.
- Open bugs (Oct 2026): pops/mistiming in seamless transitions (#94538), a clip cannot
  auto-advance to itself (#110216), no-fade transitions leave a looping clip playing (#117855),
  "at end" crossfades start late (#122956) → prefer FADE_CROSS over 1–2 beats and verify by
  recording Master (`AudioEffectRecord`) during a scripted state walk.
- Ducking: `AudioEffectCompressor` on the Music bus with `sidechain` = SFX or Dialog bus,
  ratio 4, release ~250 ms. The compressor reacts to the sidechain **peak** and multiplies the
  over-threshold dB by about 2.08 (measured 4.7.2): with speech peaking at −12 dBFS a threshold of
  −20…−30 dB ducks 7–18 dB; −17 dB gives ~4 dB. Set the threshold from the measured duck, not
  from the usual range.
- Measured in 4.7.2 with an offline `AudioStreamPlayback.mix_audio` probe (g2 row 108):
  - `AudioStreamInteractive` starts the next clip **early** by one mix block + 128 frames on END /
    NEXT_BEAT / NEXT_BAR hand-overs (640 frames = 13 ms at 512), never late.
  - `use_filler_clip` fades the target in over ~1.5 beats whatever the fade mode says; for "a
    silent beat, then tense", use a silence **clip** that auto-advances into the tense clip.
  - A switch request during a running FADE_CROSS leaves the clip stuck below full level: give
    each follow-up its own clip (`calm_down`, `calm_down_b`).
  - A hard END → START join between two loop clips (tails wrapped onto the start) steps 2 x p99
    for a tick; a 0.06–0.25 beat FADE_CROSS removes it and starts on time in 4.7.2.
  - Set `audio/driver/mix_rate = 48000`: the default 44100 resamples every 48 kHz asset and makes
    the beat 29400 frames.
  - `AudioStreamSynchronized` has no `get_bpm()` in script, but nested sync clips keep beat and
    bar sync.
  - The first play of an Ogg drops 2 priming frames; loops wrap bit-exactly.
  - `mix_audio` returns fewer frames once a playback has finished: an offline render loop must
    stop on a short return, or it never ends.
- Offline check pattern: render the interactive stream with `mix_audio` in a headless probe
  (acceptance `scripts/probe_base.gd`), locate clips in the render by sample search, and fit the
  cross-fade weights by least squares; then compare with the transition table.

**Unity 6:** `AudioSource.PlayScheduled(dspTime)` 100–200 ms ahead + `SetScheduledEndTime`,
two sources alternating for gapless segments; AudioMixer snapshots for intensity; Duck Volume.
**Unreal 5:** Quartz clocks (`PlayQuantized` on bar/beat), MetaSounds; the Harmonix plugin's music
clock (verify on the engine version in use).

## 6. In-game acceptance

Scripted walk through every state in the running game, Master recorded to WAV: transitions land
on bar boundaries (± one mix block), no clicks, ducking 3–6 dB under weapons and dialogue, no
music gaps when switching, licence manifest (soundfonts, any AI) present in `tools/music/`.
