# Out of scope — ideas the user rejected

One file per rejected **concept** (kebab-case name, e.g. `deep-squat-crouch.md`), not one per
request. Before proposing a feature, task, tool or rule, look here and match by meaning, not by
keyword ("night theme" matches `dark-mode.md`). If it matches, do not propose it again; if the
situation really changed, say which file it contradicts and why it is worth reopening.

Format:

    # <concept>
    Rejected <YYYY-MM-DD> by the user: «<their words>».
    Why: <the reason, one or two lines>.
    Instead: <what was chosen, if anything>.

    ## Prior proposals
    - <YYYY-MM-DD> — <who proposed it, in which task>

Write a file when the user turns a proposal down with a reason. A one-off "not now" is a decision
(`memory/decisions.md`), not a rejection. Do not record things that were simply already done.
